# stock_analyysis 前端 UI/UE 整体重构方案

> 版本: v1.0 | 日期: 2026-07-28 | 状态: 设计阶段

---

## 核心目标

打通 **新闻输入 → 影响解析 → 产业链传导链条可视化 → 资金博弈/预期/个股状态联动更新 → 人工审核修正** 完整交互闭环。

**解决当前痛点：**
- 模块信息孤岛
- 新闻只能文字回复
- 没有传导链路图形
- 各类状态无法直观呈现
- AI 结论缺少人工复核流程

**对标竞品短板：** 东方财富、iFinD 只有静态资讯摘要；普通 AI 投研工具仅有对话，缺少可交互、可编辑、可审核的因果传导图谱。

**现有底座：** Streamlit + ECharts 脑图 iframe；短期先改造适配现有架构；长期平滑迁移至 React 独立前端。

## 一、五大核心状态（所有 UI 的数据底座）

所有界面统一围绕这 5 类状态联动，一处变更，全界面同步刷新。

| # | 状态类型 | 包含内容 |
|---|---------|---------|
| 1 | **股票状态** | 技术位置、支撑/压力、趋势结构、波动率、15日周期情景（乐观/基准/悲观价格区间、关键触发点位） |
| 2 | **资金压力 & 资金博弈状态** | 融资盘风险、北向持仓变化、筹码分布、板块资金净流入/流出、杠杆平仓风险阈值、多空力量对比 |
| 3 | **产业链状态** | 上下游企业、供需关系、产能、订单传导、成本传导、竞争格局 |
| 4 | **预期状态** | 市场一致预期、业绩上修/下修概率、机构观点分歧、景气度阶段、远期估值预期 |
| 5 | **事件状态** | 消息性质（利好/利空/中性）、影响层级、传导时效、影响幅度、风险持续性 |

**需求原点：** 用户粘贴新闻文本 → LLM 自动解析，输出五大状态的变更假设，并生成可视化传导链条，支持人工审核编辑。

## 二、完整交互流程设计（标准闭环）

```
用户输入新闻/公告文本 →
1. LLM解析引擎（可路由DeepSeek/豆包）
    输出：
    · 事件标签、利好强度、短期/中长期区分
    · 直接影响标的、上下游传导路径
    · 对【产业链/资金/市场预期/个股估值】的冲击假设
→2. 自动渲染【交互式产业链传导图谱】
→3. 自动刷新右侧面板五大状态指标
→4. AI生成推演变化：原有15日价格区间是否需要调整
→5. 人工审核操作台：允许修改AI结论、调整传导强度、新增/删除传导链路、标记有效/无效假设
→6. 审核确认后，持久化保存事件影响模型，纳入后续周期预测因子
```

## 三、分区 UI 布局总体规划（三栏固定布局）

### 左侧栏：事件输入池 + 审核工作台

- **新闻输入区：** 文本框粘贴新闻/政策/券商纪要/公告；附件上传 PDF/截图（豆包多模态 OCR）；【启动影响解析】按钮
- **事件列表池：** 每条事件卡片展示来源、时间、AI 初判（利好🟢/利空🔴/中性🟡）、审核状态【待审核｜已确认｜废弃】；操作按钮：查看传导图谱、重新解析、编辑结论、归档
- **审核控制面板：** 影响持续周期选择（短期1~5日/中期6~20日/长期）、冲击强度滑块1~10级、传导衰减系数调整、手动新增传导节点/切断不合理链路、审核意见录入、支持驳回 AI 错误结论

### 中间主区域：交互式产业链影响传导图谱

- **节点类型：** 🟡事件节点、🔵上市公司节点、🟢上游企业节点、🟠下游客户节点
- **连接线属性：** 绿色=正向利好传导、红色=负向利空传导、粗细=影响强度、悬浮提示=传导逻辑/衰减比例/时间周期
- **交互能力：** 点击事件节点展开新闻原文+AI分析、拖拽节点调整产业链结构、双击连线修改传导逻辑和冲击强度、右键新增/阻断传导链路、仿真按钮【运行影响推演】

### 右侧栏：五大状态实时面板

- 📈 **股票状态面板：** 支撑压力、15日三套情景价格区间、趋势信号
- 💰 **资金博弈面板：** 融资风险等级、北向情绪、筹码变动预估
- 🏭 **产业链状态面板：** 供需平衡、订单预期、成本变动
- 🧠 **市场预期状态面板：** 景气度变化、机构预期上修/下修概率
- 📋 **推演汇总面板：** 整合全部状态，支持复制导出简报

## 四、关键 UE 交互细节

### 1. 新闻解析智能链路设计

- **多模态：** 图文新闻/截图公告 → 豆包 API (OCR + 图文理解)
- **深度推演：** 产业链逻辑推演、长文本政策解读 → DeepSeek
- **关键约束：** 强制输出结构化 JSON，驱动图谱渲染和状态面板刷新

### 2. 人工审核机制

1. AI 初解析 → 状态【待审核】，图谱/预测区间灰色预览
2. 投研人员审核：确认传导链路 / 删除错误路径 / 调整冲击强度
3. 点击【审核通过】→ 数据固化为有效因子，图谱颜色由灰变实色

### 3. 状态变更溯源功能

鼠标悬浮面板变动值，显示："价格中枢上调，主要驱动事件：XX新闻（日期）｜传导路径：苹果订单→立讯精密"

### 4. 场景仿真交互

用户粘贴新闻 → 自动生成事件节点和传导链路 → 右侧面板自动更新 → 人工调整传导强度 → 系统实时重新演算 → 所有指标同步刷新

## 五、竞品对比

| 平台 | 新闻处理 | 产业链展示 | 传导仿真 | 人工审核 | 状态联动 |
|------|---------|-----------|---------|---------|---------|
| 东方财富/同花顺 | 新闻列表+文字摘要 | 静态行业图谱 | 无传导推演 | 无审核流程 | 各模块互相独立 |
| iFinD/Choice | 资讯检索，基础事件标记 | 静态产业链图表 | 不具备动态冲击模拟 | 无 | 数据无联动仿真 |
| 普通 AI 投研产品 | 对话文字解读新闻 | 无图形化链路 | 仅文字描述影响 | 无法人工修正 | 预测黑盒，不可溯源 |
| **优化后 stock_analyysis** | **文本/OCR识别+结构化解析** | **交互式动态传导图谱** | **可调节强度仿真、上下游逐级传导** | **完整审核流程，区分草稿/生效假设** | **新闻→产业链→资金→预期→个股预测全链路联动** |

## 六、分阶段落地实施路线

### 阶段 0：代码基线整理（1 周）

- 统一修正项目拼写，消除隐性 404/导入异常
- 梳理所有 `st.session_state` key，制作清单，删除临时零散变量
- 抽离常量、接口配置到 `.env`，LLM 密钥、模型名称、请求参数集中管理
- 拆分巨型页面文件，按模块拆分为独立 page 组件
- 封装通用工具函数：行情请求、日志、异常捕获、token 统计
- 新建 feature 分支用于迭代新功能，不污染主分支

### 阶段 1：基础设施改造（3 周）

- **1.1 GlobalState 全局状态中心** (`core/global_state.py`)
  - 五大顶层状态分组：stock_state, capital_state, industry_chain_state, expect_state, event_state
  - 提供标准读写、变更钩子
  - 所有 UI 面板统一从此读取数据

- **1.2 MessageBus 双向消息总线** (`core/message_bus.py`)
  - 标准化 JSON 消息协议：msg_id, sender, action, payload, timestamp
  - ACK 应答机制，解决 iframe 通信不可靠问题
  - JS 侧封装 sendMessage / 监听后端推送

- **1.3 LLM Gateway 重构** (`llm/gateway.py`)
  - 任务自动路由：多模态→豆包，深度推演→DeepSeek
  - 统一异常、限流、重试、日志
  - 强制支持结构化 JSON 输出

### 阶段 2：事件解析 + 人工审核工作台（3 周）

- 重构主页面为三栏固定布局
- 左侧工作台：新闻输入、事件列表卡片、审核控制面板
- 事件解析引擎 `core/event_analyzer.py`：调用 LLM → 结构化 JSON → 自动渲染图谱
- 人工审核工作流：pending → confirmed / invalid 状态流转

### 阶段 3：动态产业链传导仿真图谱（3 周）

- 升级 ECharts 三区脑图：节点类型区分、连线可视化规则、交互功能
- 传导仿真引擎 `core/chain_simulation.py`
- JS 端实现：单击节点详情、双击连线编辑、右键菜单、仿真按钮

### 阶段 4：全链路联动 + 五大状态面板（2 周）

- 右侧面板 5 个折叠模块，全部从 GlobalState 响应式读取
- 事件审核生效后自动更新区间并标注变动溯源

### 阶段 5：优化、持久化、BUG 修复（1 周）

- 持久化模块 `core/storage.py`
- 保存事件库、产业链图谱结构、推演方案快照
- 浏览器刷新/重启系统后恢复历史推演工程

**总周期：10～12 周**

## 八、高风险点与规避方案

| 风险 | 解决方案 |
|------|---------|
| Streamlit 持续重渲染导致图谱频繁销毁重建 | 画布变更落地 GlobalState，iframe 增加缓存快照，控制局部刷新 |
| LLM 不输出标准 JSON 导致解析崩溃 | gateway 内置 JSON 清洗函数，增加重试机制（最多2次），Prompt 加约束 |
| 大量状态联动出现循环刷新死循环 | GlobalState 增加更新锁，区分「程序更新」和「人工交互更新」 |

## 九、LLM Prompt 体系（四套核心 Skill）

| Skill | 用途 | 调用位置 |
|-------|------|---------|
| Skill 1: 新闻结构化解析 | 新闻/公告→标准化JSON（event_meta, multi_factor_analysis, transfer_chain, stock_impact） | `core/event_analyzer.py` |
| Skill 2: 传导链条深度推演 | 人工修改链路后重新仿真冲击传导 | 图谱【重新仿真推演】按钮 |
| Skill 3: 单标的全景多因子诊断 | 综合事件库输出标的综合评分 | 选股面板 |
| Skill 4: 人工审核修正辅助 | 驳回/修改AI结论后重新优化逻辑 | 审核工作台 |

### 模型调度规则

```
任务类型                 → 模型选择
长新闻/复杂推演 (>2000字) → DeepSeek
短新闻/轻量解析          → 豆包
图片OCR识别             → 豆包（多模态）
专业对话                → DeepSeek
轻量对话                → 豆包
```

```json
{
    "event_meta": {
        "event_title": "事件精简标题",

        "overall_direction": "positive | negative | neutral",
        "impact_strength": 1~10,
        "impact_cycle": "short | middle | long",
        "summary": "100字以内事件摘要"
    },
    "multi_factor_analysis": { ... },
    "transfer_chain": [
        {
            "from_node": "源头节点",
            "to_node": "被影响标的",

            "direction": "positive | negative",
            "strength": 1~10
        }
    ],
    "stock_impact": { ... },
    "audit_note": "AI推演潜在缺陷"
}
```

## 十、长期演进路线

- **路线 A（短期）：** 持续基于 Streamlit 迭代，适合内部使用、小范围私募
- **路线 B（商用）：** Python 业务引擎封装为 FastAPI 后端，抛弃 Streamlit，独立 React 前端。本次所有业务逻辑可平滑迁移，无重复开发浪费。
